# SMTP-based email transport replaces Outlook COM automation

LabHerald previously sent notification email via local Outlook COM automation, which meant the sender identity was whichever user happened to be logged into Outlook on the machine running the scheduler — leaking the operator's identity and requiring a signed-in Outlook desktop client on every machine that runs it. We replaced this with `smtplib` sending directly to the company's internal SMTP relay (`smtp.intel.com:25`, no auth, no TLS — a configuration already validated by another internal tool), using a fixed service sender address (`email_from` in config.json) with no fallback to the running account's identity. All SMTP transport settings live in `config.json` (not environment variables), consistent with this tool's existing PyInstaller-EXE-plus-adjacent-config.json deployment model. This is a full replacement, not a dual-path/fallback design — `send_via_outlook` was removed entirely.

**Consequences**: `pywin32` is no longer a dependency. Before deploying to a new scheduler machine, verify it can actually reach `smtp.intel.com:25` (e.g. `Test-NetConnection smtp.intel.com -Port 25`) — this is not guaranteed on every network the machine might sit on.
